# 메시지 토큰·시간 표시 v1.0.2

실리태번 메시지의 원래 위치에 **토큰 수(`123t`)와 생성 시간(`4.2s`)**을 표시합니다.
SillyTavern 1.13.4 이상을 대상으로 합니다. 별도 서버 플러그인은 필요하지 않습니다.

## 무엇을 바꾸나요?

- 기존 토큰·시간 표시 칸의 글자, 표시용 클래스, 툴팁만 변경합니다. 칸이 없는 경우 아바타 아래에 동일한 칸을 만듭니다.
- 채팅 내용·채팅 파일·프롬프트·캐릭터 카드·프리셋·다른 확장 설정은 수정하지 않습니다.
- 프롬프트 주입, AI 생성 요청, 자동 재생성, 자체 외부 전송 기능은 없습니다.
- 저장된 토큰 수가 없으면 **실리태번 기본 토크나이저**로 계산합니다. 설정에 따라 실리태번 서버 또는 연결된 토큰 계산 백엔드로 요청이 발생할 수 있으며, 실리태번 기본 토큰 캐시가 채워질 수 있습니다. AI 답변을 생성하는 요청은 아닙니다.
- 토큰 수와 속도는 표시용 수치입니다. API 서비스의 실제 청구량과 동일함을 보장하지 않습니다.

## 새로고침해도 시간이 유지되나요?

실리태번이 메시지에 저장한 생성 시작·완료 시각이 있으면 그 값을 우선합니다.
시간 기록이 없는 새 답변은 생성 이벤트를 관찰해 보충 측정하며, **현재 브라우저의 확장 전용 저장소(localStorage)**에 시간과 메시지 식별용 해시를 저장합니다. 대화 원문은 이 저장소에 보관하지 않습니다.

- 같은 브라우저·주소·계정에서는 새로고침하거나 채팅을 다시 열어도 보충 시간이 유지됩니다.
- 계정·캐릭터/그룹·채팅·스와이프를 구분합니다. 메시지 번호가 바뀌어도 같은 메시지를 식별합니다.
- 보충 기록은 다른 기기나 브라우저로 동기화되지 않으며 채팅 내보내기에도 포함되지 않습니다.
- 사이트 데이터 삭제, 시크릿 모드 종료, 저장 공간 부족·접근 차단 시 기록이 유지되지 않을 수 있습니다. 저장 실패는 콘솔에 경고합니다.
- 보충 기록은 채팅별 최근 5,000개까지 보관합니다.
- 시간 정보가 전혀 없는 과거 답변이나 v1.0.1에서 새로고침으로 이미 사라진 시간은 복구할 수 없습니다. 토큰 수만 표시합니다.
- 내용이 변경된 답변에는 다른 내용의 보충 시간을 재사용하지 않습니다. 본문이나 thinking 원문을 수정하면 해당 답변의 보충 시간 표시가 사라질 수 있습니다.

보충 시간은 확장이 관찰한 생성 구간입니다. 검수·번역·재시도 확장의 동작에 따라 순수 모델 생성 시간과 다를 수 있습니다. 생성 도중 새로고침하는 경우는 완료된 시간 저장을 보장하지 않습니다.

## 설치·업데이트

1. ZIP을 압축 해제합니다.
2. `message-metrics-display` 폴더를 `SillyTavern/data/default-user/extensions/`에 넣습니다.
3. 기존 버전을 업데이트한다면 폴더 안의 파일을 **전부 덮어씁니다**. 새 `storage.js`, `token-jobs.js`도 필요합니다.
4. 실리태번을 완전히 새로고침하고 확장 관리에서 **메시지 토큰·시간 표시**를 활성화합니다.
5. 새 답변을 생성한 뒤 시간이 표시되는지, 새로고침 후에도 유지되는지 확인합니다.

계정 이름이 `default-user`가 아니라면 해당 계정의 `extensions` 폴더에 설치하세요.
GitHub URL로 배포하려면 저장소 최상단에 `manifest.json`과 실행 파일들을 올리세요. ZIP 바깥 폴더를 추가로 중첩하지 마세요. `auto_update`는 Git 저장소로 설치된 경우에 사용되며, 수동 ZIP 설치를 Git 저장소로 바꾸지는 않습니다. `homePage`는 실제 배포 저장소 URL이 정해졌을 때 추가하세요.

## v1.0.2 변경 사항

- 실제 ST 이벤트 순서(`GENERATION_STARTED → MESSAGE_SENT`)에서 시간 측정이 초기화되는 문제 수정.
- 보충 생성 시간의 브라우저 저장 및 새로고침 후 복원 추가.
- 현재 메시지의 생성 시각을 오래된 스와이프 시각보다 우선하여 이어쓰기·스트리밍 표시 개선.
- 중복 종료 이벤트가 완료 시간을 늘리지 않도록 수정.
- 토큰 계산을 시간 표시와 분리. 계산 대기는 최대 8초, 동시 요청은 최대 2개이며 오류 후 30초 동안 새 계산을 쉬어 갑니다. 시간 초과는 대기만 종료하며 이미 시작된 ST 요청을 강제로 취소하지 않습니다. 미응답 요청이 2개면 새 계산을 더 시작하지 않습니다.
- 채팅 전환·스와이프·메시지 교체·모델 전환 중 늦게 도착한 토큰 결과를 잘못된 화면에 적용하지 않도록 수정.
- 기본 시간 툴팁의 thinking/첫 토큰 정보는 가능하면 보존하며, 같은 칸에 다른 확장이 넣은 비어 있지 않은 시간을 반복해서 덮지 않습니다.
- 토큰 계산 요청에 관한 안내를 정확하게 수정.

## 제거

확장 관리에서 비활성화하거나 설치 폴더를 제거한 뒤 새로고침합니다.
브라우저에 보충 시간 기록은 남습니다. 해당 사이트의 개발자 도구 → Application/Storage → Local Storage에서 **`st-message-metrics:v2:`로 시작하는 항목만** 삭제하면 확장 기록을 지울 수 있습니다. 사이트 데이터 전체 삭제는 다른 확장 데이터에도 영향을 줄 수 있으므로 권장하지 않습니다.

## 검증

개발자용 회귀 테스트: `npm test` (Node.js 18 이상).
실제 기기·테마·타 확장 조합 전체에 대해 무결점 작동을 보장하지는 않습니다. 배포 전 실제 실리태번에서도 일반 생성, 검수 후 지연 표시, 스와이프, 이어쓰기, 새로고침을 확인하세요.
